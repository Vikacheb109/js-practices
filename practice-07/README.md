## 4. Структура приложения

| Файл | Назначение |
|---|---|
| `App.jsx` | Главное состояние и обработчики |
| `TaskForm.jsx` | Создание и редактирование задач |
| `TaskFilters.jsx` | Поиск и фильтры |
| `TaskList.jsx` | Отображение списка |
| `TaskItem.jsx` | Одна карточка задачи |
| `TaskStats.jsx` | Общая статистика |
| `domain/task-service.js` | Проверка данных и операции с массивами |
| `data.js` | Исходные задачи и категории |
| `variant.js` | Номер варианта и начальные фильтры |

Общий массив задач, фильтры и идентификатор редактируемой задачи хранятся в `App` через `useState`.

Форма хранит собственный черновик и сообщения об ошибках.

Дочерние компоненты получают данные через props и сообщают о действиях родителю через обратные вызовы.

## 5. Состояние и неизменяемость

Для добавления используется создание нового массива через spread, для изменения — `map`, для удаления — `filter`.

Исходный массив задач и объекты не изменяются.

Видимый список вычисляется через `selectTasks(tasks, filters)`, а общая статистика — через `getTaskStats(tasks)`.

Отдельное состояние для видимого списка и статистики не создаётся.

## 6. Компоненты и форма

Реализованы функциональные компоненты `TaskStats`, `TaskFilters`, `TaskList`, `TaskItem` и `TaskForm`.

Управляемые поля формы получают значения из состояния и обновляют их через `onChange`.

Перед созданием или редактированием выполняется `validateTaskDraft`.

Проверяются название длиной 1–100 символов после trim, приоритет и категория.

При редактировании ID и статус задачи сохраняются.

Для переключения формы между записями используется стабильный ключ `editingId`. При изменении ключа React создаёт форму с новым исходным черновиком.

Карточки получают ключ `task.id`, а не индекс массива.

## 11. Ответы на контрольные вопросы

**1. Чем JSX отличается от HTML?** JSX — синтаксис для описания элементов React внутри JavaScript. В нём используются выражения в фигурных скобках и атрибут `className`.

**2. Чем props отличаются от состояния?** Props передаются от родителя, а состояние принадлежит самому компоненту и обновляется через `useState`.

**3. Почему обычная переменная не заменяет useState?** Её изменение не сообщает React о необходимости перерисовать компонент.

**4. Когда требуется функциональное обновление?** Когда следующее значение зависит от предыдущего, например при добавлении или удалении задачи.

**5. Почему нельзя менять объект в копии массива?** Объект может оставаться общей ссылкой со старым массивом. Нужно создать новый объект.

**6. Зачем нужен key?** Он помогает React различать элементы при изменении списка. Индекс ненадёжен при удалении.

**7. Почему список и статистика не хранятся отдельно?** Они вычисляются из актуальных задач и фильтров, поэтому отдельное состояние создаёт риск рассогласования.

**8. Как дочерний компонент сообщает о действии?** Через функцию обратного вызова, переданную в props.

**9. Что такое управляемое поле?** Поле, значение которого задаётся состоянием React и обновляется через `onChange`.

**10. Почему categoryId преобразуется?** Значения HTML-полей являются строками, а ID категории в модели — число.

**11. Что происходит при смене key формы?** React пересоздаёт компонент, и его локальное состояние инициализируется заново.

**12. Почему confirm не вызывается внутри setTasks?** Функция обновления состояния должна быть чистой, а подтверждение — побочное действие.

**13. Чем отсутствие задач отличается от отсутствия совпадений?** В первом случае полный массив пуст, во втором — полный массив содержит задачи, но фильтр ничего не нашёл.

**14. Что проверяет npm test?** Предметные функции: валидацию, фильтры, статистику и изменение массивов. Сам интерфейс React проверяется вручную.

**15. Что потребуется для API в ПР8?** Добавить асинхронные запросы, состояния загрузки и ошибок, отправку изменений серверу и повторное получение задач.
