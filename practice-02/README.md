### Исправление ошибки во втором эксперименте

В исходном коде была функция:

```js
const square = (value) => {
  value * value;
};
```

При вызове `square(4)` она возвращала `undefined`, поскольку результат вычисления не передавался вызывающему коду.

Исправленная версия:

```js
const square = (value) => {
  return value * value;
};
```

Теперь вызов `square(4)` возвращает число `16`.

**Вывод по заданию:** `return` необходим для передачи результата функции. `console.log()` только выводит данные. При работе с объектами важно учитывать ссылки и различать копирование массива и копирование его элементов.

## 4. Задание 2. Модель данных и функции

### Модель задачи

Каждая задача представлена объектом с четырьмя свойствами:

```js
{
  id: 20,
  title: "Подготовить демонстрацию",
  completed: false,
  priority: "medium"
}
```

**Назначение полей:**

- `id` — уникальный положительный целочисленный идентификатор.
- `title` — название задачи.
- `completed` — логический признак выполнения.
- `priority` — приоритет задачи.

### Проверка данных

Для идентификатора используется `Number.isSafeInteger(id)` и проверка `id > 0`. Это исключает строки, дробные числа, отрицательные значения, `NaN` и бесконечность.

Название обязательно должно быть строкой длиной от 1 до 100 символов после удаления краевых пробелов методом `trim()`.

Приоритет принимает только `"low"`, `"medium"` или `"high"`. По умолчанию используется `"medium"`.

Новая задача всегда создаётся со статусом `completed: false`.

### Функция createTask

Функция `createTask(id, title, priority)` проверяет аргументы и создаёт новый объект задачи.

При успешном выполнении возвращается:

```js
{
  ok: true,
  task: {
    id: 20,
    title: "Подготовить демонстрацию",
    completed: false,
    priority: "medium"
  }
}
```

При некорректных данных возвращается объект:

```js
{
  ok: false,
  error: "Описание ошибки"
}
```

Таким образом, ожидаемые ошибки обрабатываются без аварийного завершения программы.

| `getTaskTitles` | Получение массива названий через `map` |

Функции чтения возвращают объект, массив или статистику. Поиск отсутствующей задачи возвращает `undefined`.

Функции изменения при успешной операции возвращают `{ ok: true, tasks: новыйМассив }`, а при ошибке — `{ ok: false, error: сообщение }`.

### Почему ID не равен индексу массива?

Индекс — это положение элемента, начиная с нуля. ID — постоянный идентификатор записи.

Например, задача с `id = 4` может находиться в массиве под индексом 1.

После удаления другой задачи индекс элемента может измениться, а его ID остаётся прежним.

### Почему процент возвращается числом?

`getTaskStats()` возвращает числовое значение `progress`, чтобы его можно было использовать в дальнейших вычислениях.

Метод `toFixed(1)` применяется только при выводе, поскольку он возвращает строку с округлённым значением.

### Как сохраняются исходные данные?

При добавлении используется spread массива:

```js
[...tasks, newTask]
```

При изменении выбранной задачи — `map` и копирование объекта:

```js
tasks.map(task =>
  task.id === id ? { ...task, completed } : task
)
```

При удалении — метод `filter`.

Таким образом, успешные операции создают новый массив, а при обновлении задачи также новый объект изменённой записи. Исходные массивы и объекты остаются без изменений.

## 9. Вывод

В ходе практической работы были изучены функции, объекты, массивы и организация JavaScript-кода с использованием ES-модулей.

В отличие от первой практической работы, где вычисления выполнялись над отдельными переменными, во второй работе каждая задача представляется объектом, а все задачи объединяются в массив.

Были реализованы девять функций для создания, поиска, фильтрации, изменения и удаления задач.

Для работы с массивами использовались методы `find`, `filter`, `map`, а также spread-синтаксис.

Для обработки некорректных данных применялся возврат объектов с полями `ok` и `error`. Это позволило выполнять операции последовательно, не прерывая программу при ожидаемых ошибках.

Особое внимание уделялось неизменности исходных данных. При изменении задачи создавался новый массив и новый объект изменяемой записи.

В первом задании была изучена ошибка отсутствия `return` в стрелочной функции. После исправления функция стала возвращать ожидаемое значение.

Практическая работа позволила освоить базовые принципы разделения данных, прикладной логики и демонстрационного сценария.
