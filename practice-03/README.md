## 4. Задание 1. Исследование DOM и событий

### Эксперимент 1. Поиск отсутствующих элементов

**Прогноз:** `querySelector()` вернёт `null`, а `querySelectorAll()` — пустую коллекцию.

**Ожидаемый результат:** `null` и длина `0`.

**Объяснение:** первый метод возвращает один элемент или отсутствие результата. Второй возвращает коллекцию `NodeList`, которая может быть пустой.

### Эксперимент 2. Dataset

**Прогноз:** значение атрибута `data-task-id` будет строкой.

**Ожидаемый результат:** `"23"` типа `string`, после `Number()` — число `23` типа `number`.

**Объяснение:** значения из `dataset` представлены строками. Для передачи в функции работы с задачами идентификатор необходимо преобразовать в число и проверить.

### Эксперимент 3. Статический NodeList

**Прогноз:** сохранённая коллекция не будет увеличиваться после добавления новых элементов.

**Ожидаемый результат:**

| Состояние | Старая коллекция | Новый поиск |
|---|---:|---:|
| Исходное | 1 | 1 |
| После первого добавления | 1 | 2 |
| После второго добавления | 1 | 3 |

**Объяснение:** `querySelectorAll()` возвращает статическую коллекцию. Новые элементы не появляются в уже сохранённом результате поиска.

### Эксперимент 4. Текст и HTML-разметка

**Прогноз:** строка с тегом `<strong>` будет отображена как обычный текст.

**Ожидаемый результат:** заголовок содержит буквальную строку `<strong>Это текст, а не HTML</strong>`.

**Объяснение:** свойство `textContent` не интерпретирует строку как HTML. Поэтому вложенный элемент `strong` не создаётся.

### Эксперимент 5. Распространение события

**Прогноз:** обработчик контейнера сработает при захвате, затем обработчик кнопки, после чего контейнер получит всплывшее событие.

**Ожидаемая последовательность:**

| Порядок | Фаза | target | currentTarget |
|---:|---:|---|---|
| 1 | 1 | `lab-label` | `lab-card` |
| 2 | 3 | `lab-label` | `lab-button` |
| 3 | 3 | `lab-label` | `lab-card` |

**Объяснение:** непосредственным элементом нажатия является `span`. Событие распространяется через его предков. `event.target` обозначает исходную цель, а `event.currentTarget` — элемент, на котором выполняется текущий обработчик.

## 5. Организация кода

| Модуль | Назначение |
|---|---|
| `data.js` | Исходные данные двух наборов |
| `task-service.js` | Прикладные функции из ПР2 |
| `task-selectors.js` | Фильтрация полного списка задач |
| `task-view.js` | Создание карточек и обновление интерфейса |
| `main.js` | Хранение текущего состояния, обработка событий и вызов отрисовки |

В `main.js` хранятся переменные `currentTasks` и `currentFilter`.

`currentTasks` — полный актуальный список. `currentFilter` — выбранный режим отображения.

Функция `getVisibleTasks()` формирует отдельный массив для отображения, не изменяя полный список.

Функция `createTaskElement()` создаёт HTML-карточку через DOM-методы. Для вывода названия применяется `textContent`.

`renderTaskList()` заменяет старые карточки новыми с помощью `replaceChildren()`. Сам контейнер остаётся на месте.

`renderSummary()` использует `getTaskStats()` из ПР2 и показывает общую статистику независимо от фильтра.

`renderEmptyState()` различает полностью пустой список и отсутствие совпадений по фильтру.

События обрабатываются функциями `handleTaskListClick()` и `handleFilterClick()`.

Для распознавания кнопки используется `closest()`. Обработчики назначаются один раз на общие контейнеры, что реализует делегирование событий.

После успешного изменения текущий массив заменяется результатом сервиса, вызывается `renderApp()` и восстанавливается клавиатурный фокус.

При ошибке исходное состояние сохраняется и показывается понятное сообщение.

## 13. Вывод

В ходе практической работы были изучены основные возможности DOM и обработка событий в JavaScript.

Была реализована система отображения задач в браузере с использованием данных и функций из практической работы №2.

Для поиска HTML-элементов использовались `querySelector()` и `querySelectorAll()`. Для создания и изменения содержимого — `createElement()`, `append()`, `replaceChildren()` и `textContent`.

Было изучено распространение событий, различие `event.target` и `event.currentTarget`, а также делегирование событий через общий контейнер.

Реализованы кнопки переключения статуса и удаления, три фильтра, общая статистика и обработка пустых состояний.

При фильтрации сохраняется полный массив задач, а изменения выполняются с помощью прикладных функций ПР2.

Интерфейс обновляется после каждого успешного действия без перезагрузки страницы. Отрисовка отделена от изменения данных, что позволяет повторно использовать прикладную логику при дальнейшем развитии приложения.

Особенно важным результатом стало понимание того, что изменение DOM и изменение данных приложения — разные действия: после изменения массива необходимо обновить отображение, а простое удаление HTML-элемента не удаляет задачу из модели.
