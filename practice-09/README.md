## 6. Проверка параметров

Функция `parsePositiveId` принимает только строку положительного целого числа без ведущих нулей.

После преобразования проверяется `Number.isSafeInteger`.

Недопустимые значения: `0`, `-1`, `01`, `4abc`, `1.5`, `1e2`.

Функция `parseFilters` принимает URLSearchParams и возвращает объект с полями completed, priority, categoryId и q.

Неизвестные и повторяющиеся параметры отклоняются с ошибкой `400 INVALID_QUERY`.

### Почему значение false требует отдельной проверки?

Значение `completed=false` первоначально приходит строкой `"false"`.

Использовать `Boolean("false")` нельзя, поскольку непустая строка преобразуется в `true`.

Поэтому проверяется точное совпадение со строками `"true"` и `"false"`.

### Как проверяются дубликаты?

Для проверки повторений используется Set.

При повторном имени параметра, например `q=a&q=b`, сервер возвращает `400 INVALID_QUERY`.

### Как работает поиск?

Поиск выполняется по названию задачи без учёта регистра, с использованием `toLocaleLowerCase("ru-RU")`.

Все активные фильтры применяются одновременно через логическое И.

Исходный массив задач при чтении не изменяется.

## 11. Контрольные вопросы

**1. Чем Node.js отличается от браузерного JavaScript?** Node.js выполняет JavaScript вне браузера и предоставляет средства для работы с сервером, файлами и сетью. Объекта document в обычной серверной программе нет.

**2. Что определяет маршрут?** HTTP-метод и путь. Query-параметры проверяются внутри обработчика.

**3. Чем req.params отличается от query?** req.params содержит части пути, например id из `/tasks/4`. Query содержит параметры после знака вопроса, например `completed=false`.

**4. Почему нельзя использовать Boolean("false")?** Потому что непустая строка преобразуется в true.

**5. Зачем Number.isSafeInteger?** Чтобы исключить небезопасные целые числа, которые JavaScript не может точно представлять.

**6. Почему пустая выборка — 200, а отсутствующая задача — 404?** Получение списка прошло успешно, даже если совпадений нет. Но конкретный ресурс с заданным ID отсутствует.

**7. Чем TASK_NOT_FOUND отличается от ROUTE_NOT_FOUND?** Первое означает отсутствие задачи на существующем маршруте. Второе — отсутствие самого маршрута.

**8. Чем 405 отличается от 404?** 405 означает, что путь существует, но указанный метод не разрешён. Заголовок Allow показывает разрешённые методы.

**9. Что означает meta.total?** Количество задач, которые вошли в результат после фильтрации.

**10. Почему важен порядок middleware?** Express выполняет обработчики по порядку. Неправильный порядок может перехватить запрос раньше нужного маршрута.

**11. Почему у обработчика ошибок четыре аргумента?** По такой сигнатуре Express определяет специальный middleware для обработки ошибок.

**12. Зачем createApp отделён от server.js?** Чтобы приложение можно было создавать и тестировать без постоянного запуска сервера на фиксированном порту.

**13. Что отправляем клиенту при внутренней ошибке?** Безопасное общее сообщение, статус 500 и код INTERNAL_ERROR. Стек и внутренние подробности не раскрываем.

**14. Почему CORS — не авторизация?** CORS управляет доступом браузерного JavaScript к ответу другого origin, но не проверяет права пользователя.

**15. Что добавим в ПР10?** POST, PATCH, DELETE, проверку данных записи и полноценное взаимодействие с React-клиентом.
